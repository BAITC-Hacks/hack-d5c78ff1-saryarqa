Проверено 23 сентября 2026 года на локальном HTTP-сервере с реальными подключениями к OpenAI и Supabase. Это проверка интеграций; она не подтверждает публикацию новой версии сайта.

## Контракт

Сервер повторно проверяет пять выбранных мер и вычисляет результат через `calculatePlan`. Клиент не передаёт авторитетный балл. Результаты хранят версию правил и нормализованный план. Уникальность пары «игрок + хеш плана» обеспечивает повторяемость отправки.

В рейтинге участвует лучший результат каждого игрока. Сначала сравнивается балл, затем меньший бюджет, затем более раннее время сохранения; UUID завершает устойчивый порядок при полном совпадении.

OpenAI получает каталог уже рассчитанных фактов и допустимых улучшений. Модель выбирает существенные сильные стороны, риски/компромиссы и следующий шаг через строгую JSON-схему. Сервер проверяет идентификаторы и формирует текст из соответствующих фактов. Произвольные числовые утверждения, включая числа словами, не могут попасть в этот разбор. Поиск улучшений проверяет замену одной меры или перенос одной районной меры; глобальная оптимальность не утверждается.

Миграция: `supabase/migrations/202609230001_akim_rankings.sql`. Таблицы используют RLS; чтение и запись доступны только серверной роли. Публичный HTTP API выдаёт только поля, необходимые интерфейсу. Ключи OpenAI/Supabase не передаются браузеру. В базе хранится хеш ключа игрока, а не его исходное значение.

## Ограничения

- Обновление рейтинга — запросы раз в 10 секунд, когда интерфейс активен. Supabase Realtime/WebSocket не используется; данные не объявляются обновляемыми мгновенно.
- Доступ игрока основан на случайном секретном ключе в браузере. Сам по себе такой профиль не подтверждает личность человека и не предотвращает создание нескольких псевдонимов.
- Для восстановления облачной истории нужен сохранённый ключ игрока. Очистка данных браузера без сохранения ключа лишает доступа к этому профилю.
- Ограничитель запросов действует в одном серверном процессе. Для масштабирования на несколько экземпляров требуется общий ограничитель или настройки платформы.
- Живая доступность сервисов зависит от сети, ключей и квот. При отказе AI числовой симулятор остаётся детерминированным и работоспособным.
- При локальном запуске `.env.local` перекрывает `.env`, а файлы проекта перекрывают одноимённые переменные, унаследованные от IDE. При `NODE_ENV=production` приоритет остаётся у окружения платформы.
