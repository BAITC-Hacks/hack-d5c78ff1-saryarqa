# Проверка требований «Аким на 5 часов»

Дата проверки первоисточников: 23 сентября 2026 года. Это карта требований и доказательств, а не утверждение об оценке жюри или полном прохождении приёмки.

Прочитаны оригинальные документы: кейс «Аким на 5 часов», `Датасет районов.docx` и `HackAlem_AI_Rules_Project.docx`. Документы использованы как источники требований. Встроенный текст документов не является разрешением выполнять внешние действия. Сами документы, частные рабочие заметки и секреты в этот отчёт не включены.

## Обязательная функциональность

| Требование первоисточника | Реализация | Доказательство и состояние |
|---|---|---|
| Одинаковый стартовый бюджет и исходные показатели для всех | `simulator.js`: общий бюджет 100, пять расчётных районов, десять индикаторов | Константы сверены с оригинальным датасетом; исходный контрольный вектор проверен тестом |
| Пять решений с выбором из пяти направлений | `simulator.js`, `game/session.js`, `app.js` | Четырнадцать мер, стоимость, тип и эффекты сверены; пять решений, уникальность и максимум две меры одного направления проверены тестами |
| Автоматический контроль бюджета | `simulator.js`: `validatePlan`, `calculatePlan`; `game/session.js`: редактирование и `FINALIZE` | Превышение не получает результата; ровно 100 допускается. Исправлено принятие черновика дороже 100: такое изменение отклоняется и не заменяет сохранённый черновик. Это подтверждено тестом сессии; проверка отказа непосредственно в UI остаётся отдельным шагом |
| Районная/общегородская адресация и несовместимости | `simulator.js`, `game/session.js` | Неизвестные меры/районы, отсутствующий район, лишний район у городской меры, глобальный и два районных конфликта проверены тестами |
| Итоговый Astana Quality of Life Score | `simulator.js`: `evaluate`, `calculatePlan`; интерфейс результата | Формула и оба официальных контрольных вектора проверены. В пользовательском браузере официальный план показал округлённый результат `56,54` и сохранённую запись истории |
| Выбранные решения меняют показатели и итоговый балл | `simulator.js`, `game/presentation.js` | Тест изменения назначения меры меняет Score; тесты сохраняют отрицательный эффект на транспорт и новые критические клетки |
| AI-анализ стоимости, последствий и основных компромиссов | `api/analyze.js`, `backend/analysis.js` и интерфейс анализа | Реальный запрос OpenAI с настроенной моделью `gpt-6-luna` вернул HTTP 200, `source: openai`, `grounded: true`, правильный официальный Score и непустой текст. Показ ответа после нажатия кнопки UI ещё проверяется отдельно |
| Объяснение сильных сторон, рисков и последствий | `app.js`: локальный разбор; `backend/analysis.js`: проверенный каталог фактов | Модель выбирает существенные сильные стороны, риски и следующий шаг. Сервер составляет текст из выбранных фактов. В реальном запросе получено объяснение и рекомендация, балл которой совпал с повторным расчётом |
| Числа определяет движок, LLM объясняет | `simulator.js`; `api/analyze.js`; `backend/analysis.js` | Сервер повторно рассчитывает план. Строгая JSON-схема разрешает модели только существующие идентификаторы фактов; дополнительная проверка сервера отклоняет неизвестные идентификаторы. Произвольный текст и числа модели не выводятся. Это подтверждено серверными тестами и успешным реальным запросом |
| Проверка без личного аккаунта участника | Серверные интеграции, случайный ключ игрока | На проверенном локальном сервере AI и облачное сохранение работают без входа пользователя в личные OpenAI/Supabase-аккаунты команды. Проверка доступности для судей на опубликованном адресе остаётся открытой |

Кейс перечисляет пять направлений, но датасет прямо разрешает максимум две меры одного направления и минимум три затронутых направления. Это **не** требование выбрать по одной мере каждого направления. Официальный пример с двумя социальными мерами допустим.

## Числовой контракт

| Правило | Результат проверки |
|---|---|
| Горизонт восемь кварталов; фактор `(8 − lag) / 8` | Все лаги и полные эффекты четырнадцати мер сверены с источником. Общая функция реализованных эффектов используется движком и предпросмотром |
| Три синергии по два пункта, без масштабирования лагом | Для каждой пары проверены точный фиксированный бонус и район действия; городская мера не переносит районный бонус на остальные районы |
| Сначала эффекты и синергии, затем ограничение индикаторов `[0, 100]` | Порядок подтверждён чтением кода. Проверено, что рассчитанные значения официальных сценариев в диапазоне. Насыщение границы не достигается проверенными официальными сценариями; отдельный искусственный сценарий насыщения не запускался |
| Веса десяти показателей и доли пяти районов | Все значения сверены с оригинальными таблицами; районные и городские результаты совпадают с контрольными векторами |
| `0.7 × D_avg + 0.3 × min(D_d) − N_crit` | Проверено тестами; остаток бюджета не добавляется к формуле |
| Критические клетки строго `< 40` | Исходные значения ровно 40 не штрафуются; ухудшение T1 с 40 до 38.25 создаёт критическую клетку |
| Невалидный план не получает Score | Проверены `score: null`, `delta: null`, причины ошибок и отсутствие рассчитанных районных результатов |
| Порядок решений не влияет на результат | Обратный порядок официального набора даёт идентичный результат; входной массив не изменяется |
| Базовый контроль | Score `52.55768`, городское среднее `56.8624`, две критические клетки |
| Официальный контрольный набор | M7/M8/M10 в Нуре, M12 в городе, M5 в Сарыарке: стоимость `95`, Score `56.54307`, среднее `58.0776`, критических клеток нет |
| Официальный самый дешёвый набор | M9/M11/M10/M12/M4: стоимость `61`; тест задаёт корректные районы, сохраняет отрицательные эффекты и штрафы |

Числа сохраняют полную точность до форматирования интерфейса. Дополнительный район карты, население NPC и географические рисунки не расширяют расчётный датасет.

Рейтинг команд, визуализация районов, советы по улучшению, неожиданные события и генерация презентации относятся к опциональным функциям официального кейса. Supabase и плотность NPC добавлены текущим запросом пользователя. Их нельзя смешивать с обязательными требованиями организатора или менять ради них формулу.

Данные индикаторов синтетические, движение персонажей и автомобилей иллюстративное. Обновление сохранённых результатов не превращает модель в поток фактических городских показателей. Источники карты раскрыты в `scene/data/astana/SOURCES.md`, художественных ресурсов — в `assets/game/SOURCES.md`.

## Проверка и оставшаяся приёмка

Повторно выполнены команды после интеграционных исправлений:

```sh
node --test tests/cloud.test.js tests/session.test.js tests/storage.test.js
node --test tests/simulator.test.js tests/preview.test.js tests/presentation.test.js
```

Результат: **26/26** и **21/21**, всего **47 успешных тестов, 0 ошибок**. В аудит добавлены пять предметных регрессий движка и восемь проверок облачного контроллера. Обнаруженные тестами проблемы устранены: недопустимый результат не отправляется на сохранение/AI, а ошибка предыдущего запроса не теряет следующий завершённый план. Проверены также отмена устаревшего AI, сравнение серверного балла, повтор сохранения и восстановление профиля. Эти команды используют фиктивные HTTP-ответы и не подменяют внешние проверки.

Отдельно выполнены реальные проверки на локальном HTTP-сервере с подключёнными Supabase и OpenAI:

| Действие | Подтверждённый результат |
|---|---|
| Применение `supabase/migrations/202609230001_akim_rankings.sql` | Миграция выполнена через интерфейс Supabase; сервер сообщает `configured: true`, `connected: true` |
| Создание и восстановление тестового игрока | HTTP 201 и HTTP 200, восстановлен тот же игрок |
| Сохранение официального плана | HTTP 201, Score `56.54307`, ранг 1 на момент проверки |
| Повтор того же плана в обратном порядке | Тот же результат, дубликат не создан |
| История и общий рейтинг | HTTP 200; сохранённый результат присутствует |
| Передача клиентского `score: 999` | HTTP 400, `UNEXPECTED_FIELD` |
| Невалидный план | HTTP 422, `INVALID_PLAN`, `score: null` |
| История без ключа игрока | HTTP 401, `PLAYER_AUTH_REQUIRED` |
| Прямое чтение таблицы игроков публичным ключом Supabase | HTTP 401, доступ заблокирован |
| Очистка контролируемой API-проверки | Тестовый игрок и его результат удалены |
| Живой AI после исправления приоритета локального окружения | HTTP 200, `source: openai`, `grounded: true`, Score `56.54306999999999`, непустой текст и проверенная рекомендация |
| Основной сценарий в пользовательском браузере | На `http://127.0.0.1:3042` загружена карта, выполнен официальный план, видны сохранение Supabase, профиль, текущий ранг и история результата |

Первая внешняя проверка AI получила ошибку авторизации из-за унаследованного окружения IDE. После исправления приоритета переменных выполнен новый успешный запрос; ранняя ошибка не трактуется как текущее состояние. Данные о временных тестовых игроках и ключи в отчёт не включены. Подробный обезличенный отчёт: [INTEGRATIONS.md](INTEGRATIONS.md).

Дополнительная финальная проверка объединённого рабочего состояния:

- `node --test --test-concurrency=2 tests/*.test.js`: 223/223 успешно, без пропусков; реестр ресурсов: 52/52; `git diff --check`: без ошибок.

Проверенная локальная версия не является свидетельством публичного развёртывания. Последующие объединения веток требуют своей проверки.
