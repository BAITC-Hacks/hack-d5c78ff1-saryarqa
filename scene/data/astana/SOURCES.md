# Sources and data notes

## Acquired renderer snapshot (2026-09-23)

`roads.geojson`, `intersections.geojson` and the checked-in raw
`osm-major-roads-response.json` derive from the supplied major-road query.
OSM database timestamp: **2026-09-22T08:45:51Z**. Attribution:
**© OpenStreetMap contributors**, [ODbL 1.0](https://www.openstreetmap.org/copyright).
Road weights and ranked intersections are derived importance samples, never
current traffic observations.

Public municipal geometry was retrieved on 2026-09-23 from:

- [Water polygons, layer 16](https://gis.esaulet.kz/server/rest/services/dop_sloi_geoportal_otkr/MapServer/16)
- [Road axes, layer 12](https://gis.esaulet.kz/server/rest/services/dop_sloi_geoportal_otkr/MapServer/12)
- [Building footprints, layer 18](https://gis.esaulet.kz/server/rest/services/dop_sloi_geoportal_otkr/MapServer/18)
- [Green space, layer 26](https://gis.esaulet.kz/server/rest/services/Sloi_geoportala_otkrytiy_kontur_0702/MapServer/26)
- [Historical administrative layer 4](https://gis.esaulet.kz/server/rest/services/Административные_районы/MapServer/4)

The municipal services expose no publication date or explicit reuse license in
their layer metadata. Retrieval time does not establish source currency. The
administrative layer has only four old district names, split into eight parts;
it must not be presented as the current six-district division. Requests for OSM
administrative relations timed out during this bounded acquisition.

Layer metadata and exact provenance are saved alongside the files. See
`INTEGRATION.md` for render caps, selection and the stdlib reproduction commands.
Source water/building rings and holes are preserved. Green-space coordinates
were generalized server-side by 0.000015 degrees; all municipal source Z values
were dropped to obtain two-dimensional GeoJSON.

## Original supplied seed notes

This MVP deliberately keeps the AI dataset small.

## Geometry sources
- OpenStreetMap / Overpass API — exact major-road geometry and OSM-node intersections generated by `build_astana_osm.py`.
- Astana open geoportal ArcGIS service — useful alternative/validation source for road axes and other municipal layers:
  https://gis.esaulet.kz/server/rest/services/dop_sloi_geoportal_otkr/MapServer

## Seed landmarks
Coordinates in `landmarks.geojson` carry their per-feature source and URL.
They are anchors for the simulator UI, not cadastral survey points.

## Parks
`parks.geojson` contains only park anchor points/centroids, not park polygons.
Exact polygons should later be generated from OSM or the municipal geoportal.

## Traffic importance
`traffic_corridors.json` contains a historical published congestion/load ranking used only
as an initial importance signal:
https://bulletin-geography.kaznu.kz/index.php/1-geo/article/view/1202

Do NOT present those scores as current/live traffic.

## Why no full POI database?
The simulator does not need thousands of shops, cafes, salons, etc. The AI should see a
compact city graph: major roads + ranked intersections + a small landmark set + game zones.
