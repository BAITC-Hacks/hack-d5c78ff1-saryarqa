# Saryarqa City Simulator — «Аким на 5 часов»

Веб-симулятор решений для условных районов Астаны по кейсу HackAlem AI. Пользователь распределяет единый виртуальный бюджет в 100 единиц между пятью мерами и видит, как меняются показатели районов и итоговый **Astana Quality of Life Score**. Данные синтетические: результат показывает поведение учебной модели, а не прогноз для реального города.

## Что делает первая версия

- Показывает стартовые показатели пяти районов и каталог из 14 мер по пяти направлениям: транспорт, экология, социальная сфера, безопасность и городские сервисы.
- Позволяет выбрать ровно пять уникальных мер, назначить район для районных мер и рассчитать один сценарий. Городские меры действуют на все районы.
- Проверяет бюджет, лимит не более двух мер одного направления и несовместимые сочетания. Недопустимый план не получает балл.
- Рассчитывает показатели с учётом задержки эффекта, синергий, ограничений шкалы 0–100, весов показателей и численности районов. Показывает итоговый балл и сравнение районов со стартовым состоянием.
- Показывает прогноз на восемь кварталов по исходной формуле DOCX, изменения показателей и до трёх допустимых улучшений с заменой одной меры. Каждый вариант повторно рассчитывается движком и может быть применён к плану.
- Даёт два AI-действия: разбор последствий и совет по рассчитанным вариантам. Сервер `/api/analyze` пересчитывает план сам; AI объясняет факты и компромиссы, не определяя баллы. Без рабочего серверного ключа расчёт и подбор вариантов доступны локально.
- Режимы «Игра» и «Расчёт» используют одну сессию: переключение сохраняет решения и результат. Инспектор показывает пять расчётных районов и справочный Сарайшық, которому нельзя назначить меру.
- Предпросмотр показывает стоимость, задержку и эффекты отдельной меры, но не выдаёт частичный городской балл. Изменение плана сбрасывает старый результат и отменяет устаревший AI-запрос.
- Сохраняет локальный личный рекорд в этом браузере. При загрузке балл пересчитывается из сохранённого допустимого плана; повреждённые/устаревшие записи игнорируются. Это не проверенный соревновательный рейтинг. Сам незавершённый черновик после перезагрузки не восстанавливается.

Подключена географическая сцена Астаны: шесть контуров районов, дороги, выбранные здания, вода, озеленение и достопримечательности с указанием источников. Доступны слои, вид сверху и 2.5D, перемещение и масштабирование карты, ограниченная прогулка акима по Нуре. Воспроизведение решений использует данные расчёта и поддерживает паузу, скорость, пропуск и повтор; перемещение акима и декоративный транспорт не меняют балл. При недоступности сцены расчёт остаётся доступен в калькуляторе. Реальная география и справочные сведения не подменяют синтетические показатели модели.

Художественный комплект подключён через `game/art.js`: 209 экспортов доступны по типу, проекции и направлению; все 52 позиции игрового манифеста имеют статус ready. Карточки решений, аким, жители, транспорт, объекты улучшений и элементы интерфейса используют готовые изображения. Варианты поз и ракурсов выбираются по контексту, а не загружаются одновременно.

## Запуск

Нужен Node.js **18 или новее**. Пакеты устанавливать не требуется.

```powershell
npm start
```

Откройте [http://localhost:3000](http://localhost:3000). При необходимости можно запустить `node server.js`. Открытие `index.html` через `file://` не подходит: интерфейс использует JavaScript-модули и запрос к локальному серверу. Порт можно задать переменной окружения `PORT`.

Отдельный вход в карту с игровым редактором — [http://localhost:3000/scene/dev.html](http://localhost:3000/scene/dev.html). Стрелки управляют камерой, `+`/`−` — масштабом; в режиме прогулки стрелки или WASD перемещают акима. Кнопки карты дублируют основные действия. Геоданные загружаются из локальных файлов без ключа картографического сервиса.

AI-анализ требует серверной переменной окружения `OPENAI_API_KEY`; модель задаётся необязательной `OPENAI_MODEL` (см. `.env.example`). Не помещайте ключ в клиентский код, README или Git. Без ключа симулятор и локальный разбор продолжают работать. Наличие API-маршрута само по себе не подтверждает, что внешний AI-вызов успешно проверен в этой среде.

## Как проверить основной сценарий

1. Откройте сайт: стартовый индекс должен отображаться как **52,56**.
2. Выберите M7 → Нура, M8 → Нура, M10 → Нура, M12 → весь город, M5 → Сарыарка.
3. Бюджет должен составить **95 из 100**. После расчёта итоговый индекс — **56,54** (точное значение модели `56.54307`).
4. Уберите одну меру или превысьте бюджет: сайт должен объяснить ошибку и не выдавать итоговый балл недопустимому плану.
5. Выберите другой допустимый набор: показатели и итоговый балл должны пересчитаться.

Все модульные и HTTP-проверки:

```powershell
npm test
```

Проверка манифеста ресурсов и зарегистрированных файлов:

```powershell
node tools/check-assets.mjs
```

Дополнительная проверка в настоящем Chrome: запустите сервер на порту 3010 (`$env:PORT='3010'; npm start`) и выполните `node tests/browser-smoke.mjs` в другом терминале. Нужны установленный Chrome и доступный пакет Playwright; приложение от него не зависит. При внешней установке задайте `PLAYWRIGHT_MODULE_PATH` (абсолютный путь к пакету), при другом порте — `AKIM_TEST_URL`. Отчёт и снимки сохраняются в исключённой из Git папке `.codex-private/browser-evidence`. Тест проверяет оболочку/резервный режим, а не готовую городскую сцену.

Для объединённой карты запустите `node tests/integration-browser.mjs`, задав `AKIM_TEST_URL` на адрес своего сервера (по умолчанию `http://127.0.0.1:3027`). Этот тест проверяет настоящий атлас, расчёт, воспроизведение, Нуру, две проекции и шесть ширин. Отдельный `node tests/scene-browser.mjs` проверяет схематичный стенд; задайте `AKIM_SCENE_TEST_URL`, например `http://127.0.0.1:3000/scene/dev-fixture.html`. Оба теста используют тот же внешний Playwright и Chrome. Результаты объединения и ограничения: [отчёт интеграции](docs/team/reports/integration.md).

Интерфейс передаёт выбранные меры в `simulator.js`. Движок возвращает причины ошибок либо расчётный результат. Серверный AI-маршрут независимо пересчитывает план перед отправкой уже готовых фактов модели. Баллы в интерфейсе берутся из движка; ответ модели служит только текстовым анализом. Код использует нативные JavaScript-модули и Node.js без сторонних библиотек.

## Данные и границы модели

Исходные значения, стоимости, эффекты и формула взяты из предоставленного организаторами файла `Датасет районов.docx`; постановка и критерии — из кейса `«Аким на 5 часов»`. Для запуска сайта сами DOCX-файлы не нужны: синтетический набор включён в `simulator.js`. В нём нет персональных данных. Горизонт моделирования — восемь кварталов. Эффекты мер и итоговый индекс определены условиями кейса, а не эмпирической моделью реального города.

Для карты используется ограниченная геобаза: основные дороги и их общие узлы из OpenStreetMap, контуры районов, вода и выборки зданий/озеленения из городского GIS, а также переданные точки достопримечательностей и парков. Полная база городских организаций не загружается. Источники, преобразования и ограничения описаны в [реестре геоданных](scene/data/astana/SOURCES.md) и [описании интеграции карты](scene/data/astana/INTEGRATION.md); дополнительный контекст — в [данных о городе](data/city/README.md). Происхождение художественных ресурсов и неподтверждённые права на отдельные заготовки отражены в [реестре ресурсов](assets/game/SOURCES.md).

Это не полная цифровая копия города: здания и озеленение представлены выборками, высоты и движение машин иллюстративны, дорожная нагрузка архивная. Дата действия шести муниципальных контуров и условия их повторного использования не подтверждены источником. Пять точек достопримечательностей уточнены по именованным объектам OSM; остальные используют переданные координаты без дополнительной проверки идентичности. Метки решений обозначают район, а не согласованный адрес строительства. Карта и AI не определяют новые координаты объектов и не пересчитывают формулу балла.

При отсутствии `OPENAI_API_KEY` живой AI-анализ недоступен. Локальный разбор представляет собой объяснение рассчитанных фактов, а не ответ генеративной модели. Поэтому полнота выполнения AI-критерия жюри зависит от настройки и успешной проверки серверной интеграции. Сохраняется только локальный лучший план, а не история сеансов. Командное сравнение, неожиданные события, полноценная 3D-сцена и генерация презентации пока не реализованы. Проверка объединённой версии в браузере и проверка живого AI — отдельные этапы; наличие кода само по себе их не подтверждает.

Локальный сервер разрешает только заданные публичные файлы и типы ресурсов; приватные заметки, `.env`, документация и обход пути не публикуются. Развёртывание на Vercel — отдельная проверка: нужно подтвердить включение файлов сцены/ресурсов/данных в пакет функции `/api/capabilities`, маршрутизацию и закрытость приватных путей. Локальный успешный запуск этого не доказывает.

## Источники данных

Для карты Астаны мы используем упрощённую геобазу, собранную из открытых источников.

Основной источник геоданных — OpenStreetMap (OSM). Из него используются только необходимые для симулятора объекты:

- основные магистрали;
- крупные перекрёстки;
- парки и зелёные зоны;
- ключевые городские объекты;
- транспортные узлы;
- крупные общественные здания.

Полная база 2GIS не загружается: тысячи магазинов, кафе и других второстепенных POI для работы симулятора не требуются.

Карта отображается собственным SVG-рендерером; 2GIS MapGL не подключён. Происхождение и ограничения геоданных описаны в `scene/data/astana/SOURCES.md`.

ИИ получает готовые результаты детерминированного расчёта и объясняет план. Выбор объектов и привязка координат через ИИ в текущей версии не реализованы.
